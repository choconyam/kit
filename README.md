# AI 작업 키트

AI 코딩 에이전트와 실무 과제를 할 때 쓰는 작업 규칙과 빈 문서 양식이다. 특정 과제를 위한 코드, 데이터, 결과물은 없다.

## 사용법

작업 폴더의 Bash에서 진행한다.

가장 쉬운 방법은 받기와 복사(아래 2~3단계)를 Codex에게 맡기는 것이다.

> GIT_TERMINAL_PROMPT=0 git clone --depth 1 https://github.com/choconyam/kit /tmp/kit 로 받고, 작업 폴더에서 bash /tmp/kit/apply.sh 를 실행해. 작업 폴더 안에는 받지 마.

끝나면 아래 5단계처럼 Codex를 다시 실행한다.

1. 위치를 확인한다: `pwd; git status --short`
2. 받는다: `GIT_TERMINAL_PROMPT=0 git clone --depth 1 https://github.com/choconyam/kit /tmp/kit`
   실패해도 아이디·비밀번호를 입력하지 않는다. 주소와 공개 상태를 확인한다.
3. 복사한다: `bash /tmp/kit/apply.sh`
4. "건너뜀"은 기존 파일을 보존했다는 뜻이다. `diff -u <파일> /tmp/kit/<파일>`로 비교하고 필요한 규칙만 기존 파일 아래에 덧붙인다.
   기존 `.gitignore`에는 빠진 줄만 덧붙인다: `grep -vxFf .gitignore /tmp/kit/.gitignore >> .gitignore`
5. Codex가 떠 있으면 `/quit`로 끝내고 작업 폴더에서 `codex`로 다시 실행한다. **업데이트 안내는 건너뛴다.**
   `/status`로 작업 폴더, 모델, 승인 방식이 그대로인지 확인한다.
6. `cat /tmp/kit/README.md`로 아래 "작업 중 순서와 요청문"을 본다. README.md는 작업 폴더에 복사하지 않는다.

## 작업 중 순서와 요청문

### 준비

- [ ] 과제 안내 경로, 작업 폴더와 마감을 확인한다.
- [ ] AGENTS.md, .gitignore와 docs 양식의 복사·건너뜀 결과를 확인한다.
- [ ] 건너뛴 파일은 비교하고 필요한 규칙만 덧붙인다. 기존 지침과 설정은 바꾸지 않는다.
- [ ] Codex 업데이트 안내는 건너뛴다.
- [ ] 웹 서버는 `0.0.0.0`으로 실행한다. 서버는 내가 터미널 새 탭에서 띄운다.
- [ ] Codex가 준 전체 주소를 미리보기 주소창에 붙여 넣는다. 서버 시작·종료·재시작은 내가 한다.
- [ ] Codex는 메신저를 볼 수 없다. 받은 답변은 내가 전달한다.
- [ ] Codex를 다시 실행하고 `/status`로 작업 폴더, 모델, 승인 방식을 확인한다.

### 승인 창 읽는 법

- `[… N lines] ctrl+a view all`이 보이면 **Ctrl+A로 전체를 읽은 뒤에만 승인**한다.
- 무슨 명령인지 읽기·쓰기·삭제로 구분한다. 대상 파일·폴더가 시킨 범위 안인지 확인한다.
- `rm -rf`, `--force`, `push`, `reset`, `sudo`, `pip install`, `curl | bash` 같은 단어가 있는지 본다.
- 모르면 **3번(esc)**을 누르고 "이 명령이 뭘 하는지 설명해 줘"라고 묻는다.
- 허락할 때는 보통 **1번(이번만 허락)**을 고른다.

### 첫 요청: 지침 확인과 시작 기록

경로, apply.sh가 보여 준 버전과 시각을 실제 값으로 바꾼다.

> 과제 안내(<경로>)와 docs를 읽고 적용할 작업 규칙을 다섯 줄로 요약해. 서로 다른 지침이 있으면 표시해. 그다음 키트로 복사한 파일만 커밋해. 제목은 "chore: 공개 작업 키트 적용 — 작업 규칙과 빈 양식 준비", 본문은 "출처: https://github.com/choconyam/kit @ <apply.sh가 보여 준 버전>"과 "검증: 미실행(파일 복사만)". 시작 시각은 `TZ=KST-9 date`로 확인해 STATE에 적고, 작업 마감 <HH:MM> KST와 마무리 시작 <HH:MM> KST도 적어. 기능 구현은 아직 하지 마.

### 두 번째 요청: 원본 탐색

> 원본 데이터는 바꾸지 말고, 읽기만 하는 짧은 스크립트를 만들어 실행해. 파일별 행 수와 열 이름, 한 행의 단위 후보, 열별 빈 값 수, 키 후보 열의 중복 수, 날짜·시간 열의 최솟값과 최댓값을 출력해. 숫자만 보고하고 해석·정제·가정은 하지 마. 모르는 점만 미확정으로 표시해.

### 문제 파악과 합의

- [ ] 스크립트 출력과 원본 몇 행을 내가 직접 대조한다.
- [ ] 실무자에게 작은 질문부터 직접 묻는다. 받은 답은 시각과 함께 Codex에게 전달한다.
- [ ] 사용자, 현재 업무 부담, 성공 기준, 할 것과 안 할 것을 확인한다.
- [ ] 모르는 내용은 미확정으로 남기고 합의를 확인한 뒤 구현한다.

### 구현과 마무리

- [ ] 작은 동작 버전부터 만들고 검증 출력을 확인한다.
- [ ] 단계 설명, 확인 질문과 작은 예시로 내가 이해했는지 확인한다.
- [ ] AI 제안을 확인하거나 고치면 확인 방법과 이유, 수정 뒤 검증을 DECISIONS에 남긴다.
- [ ] 검증한 작업 단위로 코드와 관련 문서를 함께 커밋한다.
- [ ] 실행·검증 결과, 한계와 다음 작업을 HANDOFF에 적는다.
- [ ] 웹 화면이 있으면 입력칸에 `<b>굵게</b>`를 넣어 글자 그대로 보이는지 직접 확인한다.

보안 점검은 다음처럼 요청한다.

> 보안 점검해. 화면 출력(textContent), SQL 파라미터, 셸 호출, 파일 경로, 비밀값, 외부 URL, 디버그 모드, 원본 데이터 수정 여부를 확인하고 항목마다 PASS|FAIL과 근거 파일:줄을 한 줄씩 보고해. 고치지는 말고 보고만.

### 감시 세션

- 두 번째 터미널의 작업 폴더에서 `codex -s read-only`로 실행한다. 토큰을 아끼려면 `/model`에서 추론 강도를 Medium으로 고른다.
- 첫 메시지는 다음과 같다.

> 너는 감시 담당이야. 파일을 고치거나 상태를 바꾸는 명령은 쓰지 마. 내가 "점검"이라고 하면 docs/AGREEMENT.md, docs/STATE.md, docs/DECISIONS.md와 git log 최근 5개를 읽고 다섯 줄로 보고해: ① 성공 기준별 진척 ② 남은 시간 대비 위험(TZ=KST-9 date로 확인) ③ 증거 없이 완료라고 한 것 ④ 합의 범위를 벗어난 것 ⑤ 다음에 할 한 가지. 칭찬은 빼고 문제만.

- "점검"은 합의 뒤, MVP 뒤, 기능 동결 전, 제출 직전에만 친다.
- 메인 세션이 "완료"나 "반영"이라고 하면 "코드와 git 기록을 보고 맞는지 확인해 줘"로 교차 확인한다.
- 조언만 받는다. 받아들인 지적은 메인 세션에 전달해 DECISIONS에 남긴다.
